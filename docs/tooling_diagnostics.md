# Native tooling diagnostic inventory

Generated by `scripts/tooling_diagnostic_inventory.py`; do not edit the table by hand.

The adapter is `eta/cst/diagnostic.{h,cpp}`. All entries retain compiler ownership and severity (typed errors are errors). Typed messages are compiler-provided or the shared diagnostic converter's kind-specific message. Unified messages, numeric code and related locations are retained verbatim. Every native kind has a generated adapter test.

A source resolver proves file identity and byte bounds. Unresolvable/default spans remain absent; providers may explicitly prove a zero-width BOF location. Module identity and related import/provider locations remain separate. Unknown enum values retain the numeric kind and message with partial classification; text-only failures use `compiler.unclassified` (status 1 unless the producer declares operation/internal failure). Unlocated deduplication includes producer, module and message. No adapter invokes expansion, loading or execution.

The reader is available as a non-executing service. Expansion can run user macro transformations, and linking expects expanded module forms; these are adapter inputs only, not automatically callable tooling services. The semantic analyzer requires expanded forms and runtime/builtin environments. Unified runtime enum members describe an available diagnostic representation, not permission to execute source for analysis. Unavailable semantic metadata must be reported as missing analysis coverage in later linter phases.
